# Cash Invoices protected visual preview

Owner requested web visual testing without activating unfinished Accounts functionality.
The existing coordinated publisher now accepts an explicit `accounts-visual-preview` mode.
Its default coordinated staff-release job and all existing release checks are unchanged.
The preview uses the same protected `github-pages` environment and deployment concurrency.

The approved application source is f4fb5a9b4b3a59f75381bf60967a2b723880f6de.
Exact-source Accountant QA 42847660585 and signed acceptance 42847661198 passed.
The broader contracts workflow 42847661006 failed at Chromium installation; subsequent
browser checks were skipped. It is not asserted as passed. Dedicated preview browser
checks run before deployment and against the published URL afterward.

`site.py` downloads only public static assets from the existing release integrity
manifest, verifies every hash against that manifest and requires the approved baseline.
It adds the preview under `previews/accounts-cash-invoices/`. No root staff assets,
release manifest bytes, APK, updater or backend is changed. Drift aborts publication.

The preview is labelled example data, with two synthetic invoices. The example-data
responses are generated by the actual Accountant read-only API using an in-memory
fixture, not from live records. The iframe has an opaque sandbox origin, in-memory
storage and CSP `connect-src 'none'` / `form-action 'none'`. Fetch is mocked and every
non-read action rejects. Form submission and other module navigation are disabled.
No user login, token, database access, export of production data or staff activation
is involved. The exact verified Accountant runtime assets are copied unchanged;
only the preview HTML adds the boundary and removes authentication-cache cleanup.

This is visual acceptance, not proof of authenticated production-accounting behavior.
Normal staff publication must still use the coordinated release mode and its gates.
