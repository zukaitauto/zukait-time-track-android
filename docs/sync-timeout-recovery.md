# Workshop timeout recovery — 21 October 2026

Production read-only evidence: statement timeouts in zukait_commit_workshop_state_v2 and workshop_state reads; matching API 500s. Active-session snapshots did not demonstrate a persistent blocking transaction, so resource exhaustion versus transient contention is not established. No record deletion, VACUUM FULL, timeout increase, schema change or paid resource change is part of this fix.

Two confirmed amplification/recovery defects: revision polling could resend a dirty save every second despite its scheduled backoff, and successful save did not reset the connection banner. The shared transport now enforces a bounded randomized cooldown across background reads and saves, honors retry hints, maintains independent read/write failure histories, preserves queues, and rejects stale success as a reason to erase a newer cooldown. Normal healthy poll cadence and explicit technician command authority remain unchanged. Deadline covers reading the response body too.

Server conflict processing is capped at three CAS attempts and a five-second budget before starting another attempt. This budget does not abort a transaction already executing. Database deadline/lock/resource errors return retryable database_busy instead of generic 500; all permission checks, authoritative preservation and financial history remain intact. This limits retry amplification; it cannot guarantee absence of future infrastructure outages or replace normalized event-oriented storage.
