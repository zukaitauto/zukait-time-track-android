# Optional signature in unpriced PDFs — disabled draft

This increment supersedes the “PDF embedding not implemented” status in SIGNATURES.md. SUP003 can explicitly include his own current recorded signature in an **unpriced** A4 checklist PDF. Other users' handwriting, prices, mandatory signing and new QC/delivery authority are not introduced. Signatures remain optional and unsigned output is the default. Price-source choice is still pending; no task/material/invoice price semantics are inferred.

Viewing/exporting handwriting requires a separate SIGNED_UNPRICED entry in private signature_writers for active SUP003 Supervisor, alongside OWN_SIGNATURE, UNPRICED document access, existing workspace access and all document/signature/Mechanical flags/settings. Defaults stay disabled/empty. Capture permission alone does not disclose ink, and ordinary unpriced output/current status never includes it. No account/grant/flag is enabled. Service-only invoker signature reader adds export and verify_export kinds; only export returns bounded ink internally. No new table or permission broadening is added. SQL is still disposable fixture material, not applied/generated migration.

The signed Edge action reconstructs the current server-owned unpriced whitelist, reads the exact signature revision pair and compares its stored SHA-256 source hash against that reconstruction. A canonical employee-name change that leaves workshop/control revisions unchanged also invalidates matching. Consent now carries the source token returned with the reviewed unpriced document. Capture rejects a different current token even when both global revisions match. Current status and export readers select by that token, and uniqueness is per checklist/revision pair/source hash. A genuinely changed print source can receive fresh consent without altering workshop records, while replacement of the same source remains rejected and all old events remain append-only. This supersedes the earlier revision-pair-only uniqueness description in SIGNATURES.md. Both actor/session and SQL viewing rights are rechecked. Verification output returns signature ID/source hash/revisions, never ink. No historic JSON, work periods or financial details are read/exported. No state/evidence/history/ledger updates occur when reading/generating a signed PDF.

The export checkbox is advertised only with the explicit signed-view capability and SUP003 identity. It starts unchecked, and the unsigned path stays unchanged. Signed preparation and every output verify the exact evidence ID/hash as well as current session/rights/revisions; changed/missing evidence, role/account/token/flag changes and late generation block output. A failed signed request never silently produces an unsigned file; the operator can deliberately uncheck the option. Web uses the existing PDF generator; native uses the existing validated bridge after verification. Once handed to browser/OS, copies remain snapshots and cannot be revoked remotely.

The separate renderer validates all signature fields/ink bounds and constructs SVG from numeric coordinates only. No arbitrary image/HTML/URI is accepted. It prints Mechanical Supervisor/SUP003 and the recorded time in Asia/Muscat, retains the checklist revision labels and states that the signature does not record QC or authorize delivery. A dedicated table row keeps the signature block together in the existing generator's pagination. This is a handwritten snapshot record, not a claim of biometric or qualified cryptographic signing.

Tests cover actual route/private SQL viewing grants, ordinary-output privacy, source-hash mismatch without revision change, grant/session revocation, no data/evidence writes, strict renderer and opt-in/no-fallback/account/flag/source-ID/hash checks. Browser qualification uses the real existing html2canvas/jsPDF generator and checks visible signature pixels in its PDF raster, multi-page A4 output, no external requests and opt-in controls at320/375/768/1280. Fixtures are synthetic; physical Android/WebView/old APK/touch/share/print/process/network/upgrade/rollback acceptance is still pending.
