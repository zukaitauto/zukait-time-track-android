# Paint bill posting — disabled server candidate

This is the first real bill-posting path, covering received Paint orders only. It is not the complete accounting stage, a usable Accountant screen or a production release. Independent server environment ZUKAIT_BILLS_ENABLED must be exactly true, supplier enablement must be true, and private bill control enabled/period dates must be explicitly configured. Defaults are disabled with no open period. No settings, grants or production data were changed; experiments/accountant-bill-posting.sql is a disposable candidate, not a generated/applied migration.

## End-to-end server flow

The actual existing Edge router sends accountant_bill_preview/post/list to a strict separate handler before the ordinary Accountant dispatcher. All other Accountant actions/rights remain intact. Existing verified custom session identity is injected, session tokens become server hashes, and the existing HMAC helper fingerprints complete immutable post intent. Caller actor/policy/fingerprint/receipt amounts are rejected. Current SQL credentials/session/roles and first-login state are authoritative even on receipt replay. Accountant and Manager remain configurable approvers; no no-self-approval rule is introduced.

Preview accepts an explicit supplier and at most20 exact Paint order IDs. An explicit immutable supplier/source link must exist. The private invoker RPC locks supplier/bill controls, authenticated credentials/session and current workshop row, then reads current Paint orders (cap10000). It rejects duplicate/missing IDs, unlocked/unreceived/future-dated/voided/NIL orders, missing prices, and orders with active returns. Orders containing returns require the future credit/return policy; no credit is inferred. Spare-part/consumables/manual source types are explicitly unsupported for posting.

Confirmed cost is recalculated from stored line totals or exact numeric quantity x price, rounded per line to OMR3; at most100 lines/order. Unknown values remain review-required. Source proof contains only ID, received cost/date and an opaque digest; customer, notes, raw lines and vendor labels stay private. The MD5 digest is a non-authorizing preview change marker, not a signature or security credential. The writer independently reads and validates the real locked source and workshop revision/cost; it does not trust a caller's proof. No historical workshop JSON or event replay is loaded.

The operator must explicitly attest that the vendor invoice was reviewed and provide its supplier, reference/date/total, accounting date, optional due date and reason. This is an authenticated manual document review recorded in the same transaction, not OCR, external vendor verification or proof that a paper invoice is authentic. SQL validates/records the current authorized reviewer; no synthetic documentAuthorityVerified flags are accepted. Source/amount/revision checks are computed inside SQL. The accounting day must be within an explicitly configured open range and no later than today in Asia/Muscat. No period/cutover policy is guessed or enabled.

Posting acquires the existing Accountant journal advisory lock, then supplier/bill control, credential/session and workshop locks in consistent order. It checks the existing workshop_accountant_commands receipt namespace before stale revision/source/period evaluation, so a lost acknowledgement cannot duplicate a bill. Current revocation/role/enablement is still checked before replay. It rejects actor/fingerprint/entity collisions, duplicate supplier invoice references and already-billed source IDs. Invoice references are stored trimmed/uppercase for uniqueness; display-name matching never determines supplier identity.

One transaction inserts the manual invoice-review record, received-material bill component, source snapshots, existing retry receipt, append-only audit and bill revision. Any failure rolls them all back. No workshop data/revision/history/live row or existing cash/expense journal is updated. No second receipt store or money ledger is introduced. Documents/bills/sources/audits are private RLS-enabled append-only records, with service UPDATE only on control.revision and no activation/configuration rights. Functions are SECURITY INVOKER with pg_catalog search_path; anonymous/authenticated execution is denied.

Owner policy is confirmed received-material costs only. A larger invoice leaves its excess PENDING_NOT_POSTED; tax/delivery charges are not added automatically. A lower invoice requires review. Bill list uses50-row keyset paging and labels payments NOT_RECONCILED; total supplier outstanding stays null/Pending. It must not imply an invoice has been fully recorded, is unpaid, or has zero historical balance.

## Qualification and hard limits

Tests exercise actual Edge dispatch/default flag/auth/role/strict body, actual handler+private SQL preview/post/list, exact received costs, manual invoice attestation, configured-period gate, pending differences, duplicate UUID/source/invoice protection, changed hash/revisions, rollback after audit insertion, current revocation/first-login, append-only/ACL/invoker settings and unchanged work/history/live/cash ledger. Native PostgreSQL17 additionally overlaps exact retries and competing revision writers. Tests contain only synthetic data in disposable databases. Current exact-head CI results are recorded in the PR/checkpoint; no production performance savings or physical acceptance is claimed.

Before activation: source corrections/returns/credit policy, finer receipt allocations for multiple/partial invoices against one PO, opening-cutover overlap, signed opening balances, wrong-bill correction/reversal, actual Accountant screens/guarded durable pending intents, native XML/PDF delivery and release/rollback/old-client acceptance remain necessary. Parts bill authority, credit posting, supplier payments, openings/bank reconciliation/payroll are not completed here. These are explicit blockers; do not enable the candidate merely because server tests pass. Full Windows master files remain unavailable. Production requires separate exact-source/environment approval.
