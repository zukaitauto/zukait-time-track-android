# Supplier read/source preview — inactive candidate

Adds a server-only reader adapter and service-only SECURITY INVOKER RPC to the audited supplier candidate. No existing Accountant route/UI imports these files. The new read_enabled control is false by default, independent of supplier-write enablement; existing role policy also applies. All SQL remains disposable experiment code, not an applied/generated migration. No production query, write, export, activation or deployment occurs.

List/detail/source-link reads validate the active verified Accountant/Manager session and completed first-login state before access. Service role cannot enable the reader. The adapter rejects client actor, source facts, costs, arbitrary limits/offsets and unrecognized fields, rechecks session identity/role after the read, and replaces unexpected database/auth exceptions with a safe unavailable error. Private RPC/schema permissions deny anon/authenticated. The control/session lock order matches the supplier writer; reads never insert receipts/audits or update last_seen.

Supplier list and per-supplier links use explicit keyset cursors,50 rows per request plus one lookahead. There is no all-supplier history load, automatic paging, polling or per-row source read. Detail returns only ID/name/active state. Link listings are recorded associations, not proof of purchase existence. Every page includes the supplier revision so a future UI can restart paging after source changes rather than treating mixed pages as one snapshot. No UI/export yet implements that workflow.

Source preview currently supports two exact immutable source types/IDs:

- PAINT_ORDER: one matching current workshop paintPurchasing.orders record, projected to safe identity/status flags only. At most10000 current orders; duplicate IDs fail review, absent IDs fail missing. Voided/NIL sources cannot become a purchase proof. No historical workshop_state_history JSON is read.
- SPARE_PART_LINE: one primary-key lookup in the existing authoritative workshop_v2_spare_part_state projection. The existing event system owns creation/correction/deletion/return state. No full event-history replay or new projection is created. Missing/deleted, invalid quantities and returned/inactive states require review.

CONSUMABLE_PURCHASE and VENDOR_BILL remain explicitly unsupported until their authoritative purchase/manual-document contracts are established. Usage/actual consumable costs do not prove supplier purchases. No fuzzy vendor-to-supplier matching is performed: only an existing explicit association returns the mapped supplier. Current vendor label contributes to the internal source digest but is not returned as a canonical identity.

A successful preview explicitly means SOURCE_EXISTS_ONLY with billingStatus REVIEW_REQUIRED. It does not prove physical receipt, invoice reference/amount, tax, a credit note or invoice allocation. There is no amount in the output and no auto bill/credit creation. The opaque SHA256 digest changes with selected source facts/mapping/revisions; it is a preview fingerprint, NOT a transaction authorization token. Source changes after the read remain possible. Future bill posting must revalidate exact authoritative source/receipt facts under its own atomic locks/revisions; the earlier source-association storage command is not thereby upgraded into a financially verified binding.

Test qualification covers strict flags/input/role/session/first-login/account-switch/safe errors; actual private SQL+adapter;50-row supplier/link paging without duplicates; existing core spare-list event projection; Paint source mapping; missing/duplicate/unsupported sources; changed source digest; privacy/no raw customer/notes/prices/lines; unchanged business/history/ledger/audit/receipt counters; and private invoker/ACL configuration. Fixtures alone seed synthetic current sources and supplier identities. Test setup writes are confined to disposable databases; reader operations are read-only.

Remaining: scoped receipt-level financial source verification, bill/credit posting contracts/transactions, wrong-link correction policy and gated existing Accountant UI with consistent paging/online/lost-ack/account-switch controls. Opening cutover and signed control totals, tax/period policies, bank attribution, supplier settlements, payroll and physical release qualification remain separate. Full Windows master files remain unavailable; direct owner decisions/handoff govern this candidate. No production rollout without separate exact-source/environment approval.
