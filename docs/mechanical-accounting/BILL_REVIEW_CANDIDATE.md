# Disabled supplier, received-cost and invoice review screen

Existing Accountant boot dynamically mounts accountant_bill_review.mjs only under exact config.billsEnabled=true (absent/off by default). This extends the current workspace, verified session/transport and durable UUID receipt recovery without a second dashboard/auth/ledger. Server environment, private supplier/bill controls, configured accounting period and Parts enablement remain independent and unchanged. No production activation.

The accountant_bill_suppliers action returns at most50 active supplier IDs/names with UUID keyset paging, following current SQL credentials/session/role/private invoker checks. It reads normalized supplier identities only. Names render as text, never establish source mappings. The operator selects Paint or Parts and enters1–20 exact source IDs. Existing locked receipt/cost preview rejects unknown/unlinked/unreceived/returned sources rather than substituting zero. Costs display exactly in OMR3.

After preview, the invoice form requires reference/date/accounting date, full invoice total, reason and an explicit manual vendor-document review attestation; due date is optional. Exact decimal-to-integer conversion uses BigInt, rejecting more than3 decimal places and unsafe values. Invoice below confirmed costs requires review. A second confirmation shows supplier, invoice reference, confirmed material bill and invoice excess Pending/not posted. It explicitly states no payment is recorded. Field edits invalidate confirmation; source edits/close/account invalidation clear preview. Reopening the supplier selector also clears invoice intent.

The confirmed immutable command carries reviewed revisions/source change markers and newly allocated request/entity UUIDs into the existing durable posting path. A lost response retains the exact reviewed command/UUIDs; the screen directs the operator to existing pending recovery rather than generating a new bill. It does not claim success while confirmation is uncertain. Server SQL recomputes actual sources and all authority/period/cost checks; manual attestation is not external vendor authenticity verification. Invoice excess is never silently added as tax/delivery expense.

Local tests: actual Accountant-page Chromium against synthetic API covers safe supplier text, exact OMR preview, responsive320/375/768/1280, below-cost rejection, excess Pending, edit invalidation, actual form confirm, lost acknowledgement and exact command/UUID retry. Existing cross-tab cash/bill/session/default-off checks remain. Real private SQL directory/receipt/posting is covered by disposable PGlite suite; no live business data. Browser API stubs are not proof of a production end-to-end posting or physical Android acceptance.

Activation blockers remain: partial/multiple receipt-invoice allocation, returns/credits/wrong-bill corrections, explicit server-reviewed rejection resolution, openings/overlap/control totals, payments and total outstanding reconciliation, source search/mapping UI, native PostgreSQL17 exact-head CI review, physical Android and old-client coexistence, release approval. Bill creation does not complete full accounting. No production migration/configuration/deployment.
