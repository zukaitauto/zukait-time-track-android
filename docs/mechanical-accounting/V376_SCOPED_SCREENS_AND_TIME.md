# V376: twelve separate Mechanical screens

Owner requested all eleven existing cards to open separate screens inside the
app for Manager and SUP003 Mechanical Supervisor, with a twelfth Time Management
card. Owner explicitly selected Mechanical-only access for SUP003's Estimate,
Estimate List, Create Job Card and Job Cards screens. Publication authorization
continues; these requests change the candidate runtime and require new evidence.

The dashboard has twelve cards in six two-column rows. Each destination has a
Back button. Checklist registration and checklist records use the established
Mechanical workspace in a separate section. WIP, QC Pending, Ready for Delivery,
Delivered Vehicles, Job Cards and Suggested Time Exceed read only Mechanical
domain records. QC/readiness reuse the existing authoritative projection.

Estimates use the existing LS / Parts + Labour editor and VAT calculation in an
isolated same-app document with a scoped adapter. They retain the official global
Zi-Qt number allocator's sequence/format and exact retries. Mechanical estimate
membership, receipts and audit are private. Linked Reception estimates can be
viewed but remain subject to their original approval/amendment controls.

Mechanical direct job creation calls the existing direct Cash/Credit/Insurance
validator and preserves its received/approval evidence, number authority,
classification, history and audit. SUP003 is accepted only in the scoped RPC's
transaction context for that single operation; the ordinary Reception API and
unscoped SQL call still reject the dedicated role. Newly created Mechanical job
identities are protected before their first MC is registered. Existing jobs are
not converted or reclassified.

Time Management searches only active registered Mechanical jobs. It assigns
technicians through existing TASK_ASSIGN receipts/links with a recorded reason.
Manager and SUP003 have equal scoped correction controls: allocations, recorded
interval correction/missing/cancelled time, unstarted cancellation and reopening.
Split time uses an existing destination allocation on the same task; assign a
destination technician first if necessary. Handover/reassignment uses the
existing Mechanical handover transaction so original time and task links remain
intact. All changes require review and a reason. The screen shows recorded actor,
role, timestamp and before/after values. Employee-session conflict tokens are
opaque; another department's history is not sent to the client.

The new time commit holds the real credential/session locks through the workshop
CAS commit and rejects changes to unrelated jobs, assignments, sessions, money,
history and audit prefixes. Shared Bodyshop time permissions are unchanged.
Per-account pending commands survive offline hiding/account changes and are
retried only by an explicit confirmation. File-origin estimate Back navigation
posts only a Back signal, with the parent checking the specific owned frame.
